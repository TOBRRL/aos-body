# A-OS Body

> **A-OS Body** 是一个围绕训练、饮食、体重、身体数据、恢复状态与历史分析构建的个人健身数据系统。  
> 它并不是一个“打卡 App”，而是 Personal OS / 个人数字孪生体系中的 Body 模块：持续记录真实数据，保留历史，形成趋势，并为后续 AI 分析和长期决策提供结构化基础。

---

## 项目定位

A-OS Body 的目标，是把日常健身中零散的数据统一到一个长期可维护的系统里：

- 训练记录
- 每日体重
- 饮食与三大营养素
- 身体档案
- 增肌 / 减脂 / 维持阶段
- 目标体重
- 睡眠与恢复状态
- 补剂 / 药物记录
- 日历与历史数据
- 趋势分析
- JSON 数据导出与恢复

整个系统强调几个原则：

1. **数据属于用户自己**
2. **原始记录优先，不把 AI 推测当成事实**
3. **尽量低录入负担**
4. **历史数据可追溯**
5. **不依赖封闭平台**
6. **可导出、可迁移、可继续扩展到 Personal OS**

当前项目采用单页 HTML + PWA 的方式实现，数据主要保存在浏览器本地。

# 功能概览

## 1. 首页

首页是每天使用频率最高的入口，目前包括：

### 今日状态

可记录：

- 睡眠时长
- 睡眠评分
- 静息心率
- 昨日训练负荷
- 主观精神状态

系统会根据这些信息生成当天状态评分。

静息心率在历史记录达到一定数量后，会以近期中位数形成个人基线，用于判断当天恢复状态。

---

## 2. 体重趋势

首页支持直接记录每日体重。

同一天重复记录时，会覆盖当天体重，而不会生成重复数据。

支持三个时间范围：

- 7 日
- 30 日
- 90 日

趋势模块包括：

- 当前体重
- 区间体重变化
- 记录次数
- 每日体重原始曲线
- 7 日移动平均线
- 7 日均重
- 近 14 日体重变化速度
- 阶段目标进度
- 目标体重参考线

如果当前处于增肌或减脂阶段，还会显示：

- 阶段起始体重
- 目标体重
- 当前距离目标体重
- 目标完成进度
- 当前体重趋势是否朝目标方向移动

系统目前只进行趋势反馈，**不会根据趋势自动修改热量目标**。

# 饮食系统

饮食页面按一天六个餐次记录：

- 早餐
- 午餐
- 晚餐
- 训前
- 训后
- 其他餐

每一餐手动记录：

- 碳水
- 蛋白质
- 脂肪

热量自动按：

```text
碳水 × 4
+
蛋白质 × 4
+
脂肪 × 9
```

计算。

---

## 饮食记录口径

A-OS Body 当前采用“主要营养属性记账法”。

例如：

- 米饭主要记碳水
- 肉类主要记蛋白质
- 油脂主要记脂肪

并不是完整还原每种食物的全部宏量营养素。

因此目标热量中保留了相应的记录修正系数。

---

# 当前热量计算逻辑

基础公式：

```text
BMR =
体重 × 9.99
+
身高 × 6.25
-
年龄 × 4.92
+
性别修正
```

男性：

```text
+ 5
```

女性：

```text
- 161
```

无运动总消耗：

```text
BMR ÷ 0.7
```

力量训练消耗参考：

男性：

```text
新手：150 kcal
有基础：200 kcal
老手：250 kcal
```

女性：

```text
新手：100 kcal
有基础：150 kcal
老手：200 kcal
```

训练日平衡热量：

```text
无运动总消耗
+
力量训练消耗
+
有氧消耗
```

休息日平衡热量：

```text
无运动总消耗
+
有氧消耗
```

---

## 增肌

当前记账目标：

```text
平衡热量 × 0.84
```

其中近似对应：

```text
1.05 增肌盈余 × 0.8 主要营养属性记账修正
```

宏量营养素：

```text
蛋白质 = 1.5 g / kg
脂肪 = 1.0 g / kg
```

碳水由剩余热量倒推：

```text
碳水 =
(
目标热量
-
蛋白质热量
-
脂肪热量
)
÷ 4
```

参考碳水区间：

```text
3.5–4.5 g / kg
```

---

## 减脂

当前记账目标：

```text
平衡热量 × 0.64
```

宏量营养素：

```text
蛋白质 = 1.5 g / kg
脂肪 = 0.8 g / kg
```

碳水由总热量倒推。

参考区间：

减脂初期：

```text
2.5–3.0 g / kg
```

减脂末期：

```text
2.0–2.5 g / kg
```

---

## 维持

当前记账目标：

```text
平衡热量 × 0.8
```

维持阶段暂不强制显示固定宏量营养素配额。

# 组间休息

默认组间休息：

```text

```

支持：

- +30 秒
- 提前结束
- 倒计时结束提醒
- 超时继续记录

## 同类训练对比

历史训练会与上一次同类型训练进行比较。

目前主要参考：

- 总容量
- 总组数
- 相同动作估算力量

估算力量采用 Epley 公式：

```text
1RM ≈ 重量 × (1 + 次数 / 30)
```

# 数据存储与隐私

A-OS Body 当前主要使用：

```text
localStorage
```

也就是说：

- 个人数据默认不会上传到 GitHub
- GitHub Pages 只托管程序代码
- 体重、饮食、训练等信息保存在当前浏览器 / 当前站点存储中

因此：

**清除浏览器网站数据可能导致本地数据丢失。**

建议定期使用：

```text
全部导出
```

进行备份。

# PWA

A-OS Body 支持 PWA。

可以通过 GitHub Pages 部署后安装到：

- Android 桌面
- Windows
- 支持 PWA 的浏览器环境

PWA 主要文件：

```text
index.html
manifest.webmanifest
sw.js
icons/
```

Service Worker 用于：

- 页面缓存
- 基础离线访问
- PWA 更新

每次重大更新时需要同步提升缓存版本。

例如：

```javascript
const CACHE = 'aos-body-v2.9-20261017';
```

否则设备可能继续读取旧页面。

# 当前限制

A-OS Body 目前仍有一些明确限制。

## 1. 数据仍以浏览器本地存储为主

没有账号体系，也没有正式云同步。

换设备需要手动：

```text
全部导出
→ 新设备导入
```

---

## 2. Health Connect / 手环尚未自动同步

当前睡眠、静息心率等仍主要依靠手动录入。

未来可以考虑：

- Health Connect
- Apple Health
- 厂商 API

但前提是保证数据所有权和兼容性。

---

## 3. 营养数据不是完整食物数据库

当前设计优先追求：

- 低录入负担
- 实际可长期坚持
- 主要营养属性记录

并非替代专业营养数据库。

---

## 4. 训练动作分类不是严格解剖学数据库

动作分类主要以实际训练使用体验为目标。

复合动作可能同时刺激多个肌群，因此某些动作会合理出现在多个目标肌群下。

---

## 5. 当前分析属于训练辅助

估算 1RM、体重趋势等用于长期趋势观察。

不能替代：

- 医疗诊断
- 康复评估
- 专业运动医学检查

# 设计哲学

A-OS Body 的核心不是“记录越多越好”。

而是：

```text
记录真正有价值的数据
↓
保留历史
↓
形成趋势
↓
理解变化
↓
做出行动
↓
继续反馈
```

也就是：

```text
数据
→ 分析
→ 行动
→ 反馈
```

最终目标是让个人数据成为长期可积累、可分析、可迁移的资产。
